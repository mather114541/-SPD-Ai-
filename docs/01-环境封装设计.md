## 二、核心游戏机制理解（已读源码确认）

### 1. 地图与观测（`Level.java`）

地图是**一维索引数组**，`width()×height()` 网格，`length()=width*height`。

- `int[] map` — 每格地形类型（`Terrain` 常量：墙、地面、水、门、楼梯等）
- `boolean[] visited` — 已访问过的格子（长期记忆）
- `boolean[] mapped` — 已探索/映射的格子
- `boolean[] heroFOV` — **英雄当前视野内的格子（当前帧可见）**
- `int viewDistance` — 视野距离（默认 8）
- `int entrance / exit` — 入口/出口（楼梯）位置
- `ArrayList<LevelTransition> transitions` — 层间传送点

**地形属性掩码（每格一个 boolean）**：
`passable`（可通行）、`solid`（固体/墙）、`water`（水）、`pit`（深坑）、
`losBlocking`（阻挡视线）、`secret`（秘密门）、`flamable`（可燃）、`avoid`（陷阱）

**实体位置表**：
`HashSet<Mob> mobs`、`SparseArray<Heap> heaps`（地面物品堆）、
`SparseArray<Trap> traps`、`SparseArray<Plant> plants`、`HashMap<Class,Blob> blobs`

**坐标换算**：`cellToPoint()/pointToCell()`（一维↔二维）、`distance()/adjacent()`

> **对 RL 的价值**：`map`+`heroFOV`+`visited` 正好构成"战争迷雾"的完整信息，
> `mobs/heaps/traps` 可直接枚举成特征，`passable/solid/water` 是天然的网格通道编码。

### 2. 回合推进（`Actor.java`）

- **时间驱动调度**，非回合轮换：每个角色有 `time`，谁的时间最小谁行动
- `Actor.process()` 选出最小 `time` 的角色，调用其 `act()`
- **阻塞模型**：无角色可行动时 `Thread.currentThread().wait()`，等待玩家输入后 `notify()`
- 优先级：`HERO_PRIO=0`（英雄先于怪物），`MOB_PRIO=-20`，`BUFF_PRIO=-30`

> **改造难点（核心）**：`process()` 的 `wait/notify` 阻塞 + UI 依赖（`Game.switchingScene()`、
> 角色 `sprite`）是 RL 环境必须绕过的。需要一个**同步、单步推进**的接口。

### 3. 玩家动作（`HeroAction.java` + `Hero.java`）

动作是**参数化**的，每个动作带位置或目标：

| 动作 | 参数 | 说明 |
|---|---|---|
| `Move` | 目标格 | 移动（含寻路） |
| `Attack` | 目标 `Char` | 攻击 |
| `PickUp` | 格 | 拾取 |
| `OpenChest` | 格 | 开箱 |
| `LvlTransition` | 楼梯格 | 上/下楼 |
| `Unlock` | 门 | 解锁 |
| `Interact` | `Char` | 与 NPC 交互 |
| `Buy` / `Mine` / `Alchemy` | 位置 | 商店/挖掘/炼金 |

**Hero 行动循环（`Hero.act()`）**：
- 若 `curAction == null` → `ready()` 置 `ready=true`（等待输入）
- 若 `curAction != null` → 分发到 `actMove/actAttack/actTransition...` 执行，然后 `ready=false`

> **对 RL 的价值**：设置 `hero.curAction = new HeroAction.X(...)` 即可注入动作。
> `ready` 字段标志"该轮到 AI 决策了"。

### 4. 全局状态中枢（`Dungeon.java`）

静态字段：`hero`（Hero）、`level`（Level）、`depth`（层数）、`branch`、
`gold`（金币）、`energy`（能量）、`seed`（随机种子，**可复现**）、`challenges`

`Dungeon.newLevel()` 生成新关卡；`Dungeon.seedForDepth()` 按种子生成层。
`Dungeon.observe()` 更新视野（英雄可见范围）。

### 5. 英雄与背包（`Hero.java` + `Belongings.java`）

- `Hero`（继承 `Char`）：`HP`/`HT`（当前/最大血量）、`STR`（力量）、`lvl`（等级）、
  `exp`（经验）、`heroClass`（职业）、`pos`（位置）、`ready`
- `Belongings`：装备槽（`weapon/armor/artifact/misc/ring/secondWep`）+ `backpack`（背包），
  实现 `Iterable<Item>` 可遍历全部物品

## 三、RL 环境接口设计

采用 **Gymnasium 风格**接口，与 Python 侧训练框架对接。

### 1. 核心接口

```
reset(seed)  -> observation          # 按种子新建一局游戏
step(action) -> (observation, reward, terminated, truncated, info)  # 执行一步
```

**step() 内部逻辑（改造核心）**：
1. 根据 `action` 构造 `HeroAction` 并赋给 `hero.curAction`
2. **同步推进回合**：反复让时间最小的 actor `act()`，直到英雄再次 `ready`
   （即一轮完整回合：英雄行动 + 怪物行动 + buff 结算）
3. 收集观察、计算奖励、判断终止（死亡/胜利/达到目标层）

### 2. 观察空间（Observation Space）

| 通道 | 内容 | 维度 |
|---|---|---|
| 地形 | `map[]` 按 Terrain 编码 | N（每格 1 值） |
| 实体 | 怪物/物品堆/陷阱/植物，编码种类 | N |
| 视野 | `heroFOV[]`（当前可见） | N |
| 记忆 | `visited[]`/`mapped[]`（迷雾） | N |
| 英雄向量 | HP/HT/STR/lvl/exp/pos/gold | ~10 |
| 背包摘要 | 物品类型/数量的固定窗口编码 | 固定窗口 |

> 地图尺寸随层变化，需统一 pad/缩放为固定网格（MVP 先固定小地图）。

### 3. 动作空间（Action Space）

**MVP 阶段（最小可用）**：移动 8 方向 + 等待/拾取 = 9 个离散动作。
站在楼梯格时自动触发 `LvlTransition`（上下楼）。
**扩展阶段**：攻击（对相邻敌人）、使用/装备物品、施法。

### 4. 奖励设计（稀疏奖励）

- 下到更深一层：`+1`
- 击杀敌人/获得经验：小正奖励
- 受到伤害：小负奖励
- 死亡：`-1`（终止）
- 探索新区域：极小的正奖励（可选，缓解稀疏性）

> 奖励的精确权重属于训练阶段的调参工作，环境只负责暴露事件（升级、扣血、死亡、换层）。

### 完成内容

   - `GameScene.java`：45 个 void + 4 个 boolean 静态方法批量加 `if (rl.RLMode.headless) return[ false]`

   - `Hero.java`：`ready()/speed()/interrupt()` 里 UI 调用加 headless 保护（`QuickSlotButton`、`GameScene.resetKeyHold`）

### 新增 RL 代码（`rl-src/rl/`）
| 文件 | 作用 |
|---|---|
| `RLMode.java` | `headless=true` 全局开关 |

| `TestTransition.java` | 定向下楼换层测试（含 debug 诊断） |

### 环境规格
- **动作**：9 离散。0-7 = 点击 8 方向相邻格（`Hero.handle` 自动判定移动/攻击/拾取/开门/上下楼）；8 = 点击自身（等待/拾取/上下楼）
- **观察**（定长 int[]，len = 3×地图格数 + 7）：`地形 lv.map` + `实体编码(0空/1怪/2物品/3陷阱/4楼梯)` + `视野 heroFOV` + `元信息[depth,pos,HP,HT,STR,lvl,gold]`
- **奖励**（稀疏）：换层 +1、击杀 +1、受伤 −1、死亡 −1（终止）
- **终止**：英雄死亡 或 达到目标层（默认 3）

### 验证结果（关键输出）
- 无头建局：`LEVEL OK len=1591 w=37 h=43 depth=1 mobs=11`
- 移动+完整回合：`after turn: pos=240 ready=true hp=20/20`
- 换层（processTurn 路径，清怪后）：`depth=2 pos=533 r=1` ✅
- Python 协议驱动 10 步：每次 `OK len=5056 ... reward=.. done=..` ✅

### 关键结论 / 陷阱
- **换层不走场景系统**：`Level.activateTransition` 原本切到 `InterlevelScene`（headless 下不驱动）→ 改为 headless 直接 `depth++ + newLevel + switchLevel`。
- **怪物会打断英雄换层**：teleport 到楼梯被怪发现时，怪在回合里 `hero.interrupt()` 清掉换层动作——这是**正常游戏逻辑**（真实玩家同理），非缺陷。
- **classpath 顺序**：`build\classes` 必须在 jar 之前，否则取到 jar 旧类。
- **编译反编译源码**会暴露额外泛型退化，按已修模式处理。

## 七、第二阶段实施记录（特征工程 + 观察定长化）

> 状态：已完成。观察空间重构为**定长向量**，背包/装备/状态特征编码正确并通过验证。

### 背景：观察必须定长
第一阶段观察长度 = 3×地图格数 + 7，随关卡尺寸变化（1591~1697 格）。RL 网络需要固定输入维度，因此必须定长。

### 新观察布局（定长，OBS_LEN = 1417）
以**英雄为中心 21×21 局部窗口** + 全局聚合特征，彻底消除对关卡尺寸的依赖。第二阶段深化新增**具体物品识别段、植物种子段**与**陷阱信息同权**：

| 段 | 偏移 | 长度 | 内容 |
|---|---|---|---|
| 地形窗口 | 0 | 441 | 21×21 以英雄为中心，越界填 0 |
| 实体窗口 | 441 | 441 | 0空/1怪/2物品/3陷阱(仅可见)/4楼梯 |
| 视野窗口 | 882 | 441 | heroFOV |
| 元信息 | 1323 | 7 | depth,pos,HP,HT,STR,lvl,gold |
| 全局聚合 | 1330 | 6 | 到入口/出口距离、已探索格数、怪物数、物品堆数、陷阱数 |
| 装备+背包 | 1336 | 26 | 装备槽6×2(类别,等级) + 背包计数14 |
| 具体物品识别 | 1362 | 26 | 关键药水12 + 关键卷轴12 + 未知药水 + 未知卷轴 |
| 植物种子 | 1388 | 13 | 13 种植物种子（Plant.Seed 各子类） |
| 状态 | 1401 | 16 | 饥饿1 + 关键状态15 |

- 常量：`OFF_W_TERRAIN=0 / OFF_W_ENTITY=441 / OFF_W_FOV=882 / OFF_META=1323 / OFF_GLOBAL=1330 / OFF_BELONG=1336 / OFF_ITEMD=1362 / OFF_SEED=1388 / OFF_STATUS=1401`
- **植物种子**：v4.0.0 种子是 `plants.Plant` 的**内部类 `Plant.Seed`**（按文件名搜不到），13 种植物各一个 `Sungrass.Seed`（阳春草之种）、`Earthroot.Seed` 等；战士自带种子袋 `VelvetPouch`，种子经踩踏高草获得。**`backpack` 的迭代器会扁平展开子袋**，一次遍历即覆盖种子袋内种子。
- **信息与玩家同权**（关键）：
  - 具体物品识别段**只统计已鉴定**的药水/卷轴，未鉴定的一律计入"未知药水/未知卷轴"——AI 不能比玩家提前看到未鉴定物品的真实类型。
  - 实体窗口的陷阱**只在 `Trap.visible` 时才编码**——隐藏陷阱（未探测）AI 看不见，和玩家一致。
- **陷阱回避奖励**：踩到激活陷阱额外 −1，强化模型避让（受伤 −1 已在）。
- 物品大类编码：0其他 1药水 2卷轴 3食物 4武器 5护甲 6戒指 7法器 8魔杖 9钥匙 10炸弹 11石片(Runestone) 12露珠 13金币
- 全局特征通过 `Level.distance / mapped / visited / mobs / heaps / traps` 聚合本层摘要，补偿窗口裁剪丢失的全局信息。

### 本次修复
1. **布局长度 bug**：饥饿重复编码且 `N_STATUS=15` 实际写 16 位 → 重排为装备26 + 状态16，饥饿移入状态段，索引不再越界。
2. **`Stone` 类不存在**：石片父类是 `items.stones.Runestone`，改用之。
3. **`Buff` 无 `level()`**：饥饿用 `Hunger.hunger()`。
4. **`SparseArray.size` 是字段非方法**：`lv.heaps/traps.size`。
5. **`HighGrass.trample` UI 耦合**（首次暴露的 jar 原版类）：踩高草触发 `Game.scene()` NPE → 反编译版加 `!rl.RLMode.headless` 短路并**编译覆盖 jar**（此前该类一直用 jar 原版，无 headless 保护）。今后凡遇"用 jar 原版导致的 UI NPE"，均按此模式：改反编译源码 → 编译进 build\classes 覆盖。
6. **`SewerLevel` SURFACE 过渡弹窗**：英雄上楼回地面时 `WndMessage` 构造 NPE → headless 下短路（阻止上楼），另修复其渲染类 `Sink` 的 CFR 反编译 `float f` 未初始化退化。
7. **种子段双重计数**：`backpack` 迭代器会**扁平展开子袋**（种子袋 VelvetPouch 内种子也出现在 backpack 遍历中），最初的 encodeSeeds 又显式遍历 Bag → 种子被计 2 次。删掉 Bag 分支、只靠扁平遍历一次统计后修复（附带发现：背包计数/药水卷轴统计的扁平遍历同样能覆盖子袋内物品）。

## 八、用药策略可学习化（动作空间扩展）✅

### 核心理念（用户明确纠正）
**目标是让神经网络通过试错自己学会"何时用药"，而不是环境当保姆自动用药。**
因此用药不作为环境自动触发的启发式，而是作为**离散动作加入动作空间**，由网络在
每个回合自主决策是否用、用哪个。

### 动作空间（9 → 12）
| 动作 | 含义 |
| --- | --- |
| 0–7 | 移动八方向 |
| 8 | 原地等待 / 点自身格 |
| 9 | 喝已鉴定治疗药水（`PotionOfHealing`，`execute(hero, DRINK)`） |
| 10 | 喝已鉴定力量药水（`PotionOfStrength`，`execute(hero, DRINK)`） |
| 11 | 读已鉴定升级卷轴（`ScrollOfUpgrade.upgradeItem(weapon)` + `detach`，升级当前武器） |

### 关键设计
- **信息与玩家同权**：用药只针对**已鉴定**药水/卷轴；未鉴定一律不碰（AI 不知道是哪瓶）。
- **动作失效机制**：物品缺失或未鉴定时，用药动作失效（不消耗物品、不推进），等效浪费一回合等待 → RL 学会不要选无效用药动作。
- **奖励塑形**（合法 RL 技巧，帮助稀疏信号学习）：
  - HP 上升 +1：让 RL 从信号学会"血低喝治疗药水"（SPD 治疗为持续回血，需提前喝）。
  - 用药动作执行成功 +1：引导力量药水 / 升级卷轴这类无即时效果的长期增益。
  - 叠加原有惩罚：踩激活陷阱 −1、死亡 −1、受伤 −1；换层 +1、击杀 +1。
- **专家规则作为基准而非保姆**：`RLItemPolicy` 不再自动触发，仅保留"单动作执行器 `applyAction(h, action)`"供环境调用，让网络自己做决策。

### 无头化新增修复（均已编译覆盖 jar）
- `GameScene.cancel()` 缺 headless 保护 → NPE（补保护 + 修 CFR 退化：`void var13_33/37` 补为 `int var13_33=0`/`Ankh var13_37=null`、`blocker` 改回 `PointerArea`、`dropped` 补泛型 `ArrayList<Item>`）。
- `Potion.drink()` 音效 + `hero.sprite.operate` headless NPE → 短路。
- `Potion.brew()` CFR 变量混淆（`void var3_7/3_8`、potion 块作用域）→ 重写统一变量。
- `PotionOfStrength.apply()` 的 `hero.sprite.showStatusWithIcon` NPE → 短路。
- `ScrollOfUpgrade.upgrade/weakenCurse/removeCurse` 的 `hero.sprite.emitter` NPE → 短路。
- `Healing.act()/fx()` 的 `target.sprite` NPE → 短路（保留回血核心逻辑）。

无物品力量药水动作 → STR=10 未变（动作失效）✅
有力量药水 → STR 10→11，已消耗 ✅

### 遗留 / 待定
- 力量药水"尽早喝"、升级卷轴"攒好武器再升"这类**专家策略本身的信息**，目前主要靠奖励塑形让 RL 学；若后续想让 AI 开局更快站稳，可考虑用这些规则生成**行为克隆（行为克隆）初始策略**，但这不是环境保姆，而是训练初始化。

## 九、战斗策略可学性评估与辅助路线（探讨，未实施）⚠️

### 结论
用户质疑"纯 RL 不做干涉能学会伏击/卡视野/地形逐个击破吗"。诚实评估：**基础策略纯 RL 可学，
高级战术（卡视野伏击、一打多地形逐个击破）在 i9+4060 有限算力下基本学不会**，非理论不可行，而是
三个现实原因：

1. **稀疏 + 长时延奖励**：伏击收益在"站位→怪看不见→出手"几步后兑现，信用分配难，需海量样本。
2. **观测缺显式地形特征**：21×21 地形图未显式编码门/高草/视线遮挡，网络需额外学一层视觉推理。
3. **算力量级**：roguelike 纯 RL 从零学需数百万回合（NetHack-NLE 先例），本机算力难支撑到泛化。

### 边界（关键）
- **保姆** = 环境替 AI 做决策（先前自动用药是错误，已废弃）。
- **辅助** = 不改决策、只改"学什么更容易/信号更清晰"，决策仍由网络自主出 → 不违背用户理念。

### 候选辅助路线（未定方案，待用户拍板）
- **A. 观察特征工程**：在观察段显式编码相邻格"门/高草/墙/视线遮挡"，降低网络推断地形机会的难度。
- **B. 辅助奖励塑形**：伏击命中 +1、无伤击杀 +1、空挥惩罚 → 把"好策略"信号喂给网络。
- **C. 行为克隆 / 课程学习**：用攻略规则生成行为克隆初始策略，RL 在此基础上改进（初始化，非保姆）。
- **D. 技能抽象**：把"退到掩体""接近可视怪"封装成宏观动作，降动作维度。

### 建议推进顺序
先纯 RL 基线跑通（验证环境 + 学基础）→ 加 A+B（特征 + 奖励塑形）→ 若仍卡再 C（行为克隆初始化）。
此节仅为可行性探讨，尚未进入实施。

## 十、换层课程诊断与 ON_EXIT 特征（2026-10-09，第三阶段）

### 换层瓶颈诊断（已证实）
- 换层动作链**本身是通的**：`handle(h.pos)`(action8) → `HeroAction.LvlTransition` → `actTransition` → `Level.activateTransition`（headless 分支直接改 depth+switchLevel）。**专家轨迹 traj2/traj3 的 reached=23/60 证明专家能通过 action8 换层**。
- 但 **BC（单步克隆）与 PPO（多次 10 万步）都换层恒 0**（avg_depth 恒 1.00、targets 恒 0）。
- 根因：换层是**"走到出口格才触发"的长程稀疏离散动作**。OFF_EXIT（8 方向扇区出口计数）只给了"出口在哪个方向"，**无法精确识别"自己正站在出口楼梯格上"这个状态**，策略学不到"站出口格 → 按 action8"。

### 换层课程失败记录（奖励/引导多次调整均无效）
- 阶段1（换层奖励=0，站出口邻格+10）：换层 0
- 阶段2（换层 50+80p）：换层 0
- 阶段2 提高（换层 100+200p=300 上限）：换层 0
- 加出口格引导（出口格+20 / 邻格+10）：换层 0
- 原因：换层=终止，站出口格每回合+20 比换层终止更稳定；且长程信用分配失败。
